## 2. 1 ファイルにすると得るもの

1. **受け入れテストという軸**。木にいちばん欠けているもの。`scripts/recheck_known_issues.sh` は実質、版ごとの受け入れテストで、「5 GB の GeoParquet を丸ごと取らずに読めるか」「日本語属性は通るか」のような**実際の質問**に結果を付ける形に整えられる。試作に 14 本置いた（結果はすべて `untested`。盲検の実行はまだ）。
2. **範囲外の明示**。「terrio の最新版は？」「gdalwarp の全オプションは？」に、範囲外と答えられる。
3. **`volatile` と版の明示**。terrio の事実は数日で変わる。「いつの版の話か」を答えの型にできる（試作の `agent-contract`）。
4. **状態の語彙の整理**。`played` / `read-docs` を `verified` / `stated` に、`stale` を `volatile` に対応づけて、確かさの 5 つの区別を保てる。
5. **持ち運べる**。kcai の原則 12（閉じた環境でも読める版つきの束）と、`QUESTIONS.md` の「版つきの束を実装するか」への、**最小の答え**になる。
6. **出来事の層**。`plays/` と `DECISIONS.md` の出来事を、`/traces/` → `/lessons/` の循環に載せられる（GDAL の版依存、投稿前に直った下書き、定期実行の push 失敗など）。

## 3. 1 ファイルにすると失うもの・危ういもの

1. **大きさ**。`knowledge/` は 3,647 行・約 21.6 万字、`plays/` と `drafts/` を足すと約 33 万字。**全部を 1 ファイルに入れると、多くの対話型 AI の文脈に収まらない**。CONCEPT §12-6 と §12-18 も、数千行の単一ファイルで通読できないエージェントが出たこと、約 900 行で出力できない環境があったことを記している。試作は **290 行（約 2.8 万字）に蒸留**した。つまり「ツリーを 1 ファイルにする」は、**結合ではなく蒸留**になる。
2. **細部の喪失**。再現手順、数値の表、版ごとの確認の履歴は、蒸留で落ちる。試作は `kcai:<id>` で木の踏み跡を指すが、携帯先に木がなければ辿れない。
3. **GitHub での読み・コメント**。hfu が踏み跡 1 本ずつ読んでコメントする使い方（`reviewed_by`）は、1 ファイルでは不便。
4. **CI・索引・公開ページ**。`validate_knowledge.py`、`knowledge/README.md`、公開ページの一覧は、木を前提にしている。
5. **更新の同期**。蒸留は手作業。木が日々更新されるので、`terrio.md` の版つきの事実はすぐ古くなる（`/inventory/sync-status`）。自動生成は、蒸留である以上、機械的にはできない部分が多い。
6. **kcai との関係**。kcai-terrio は kcai の最初期のインスタンス（共有の単位は踏み跡 1 ファイル）で、木をやめると kcai の実験の意味が薄れる。CONCEPT §4 は、複数ファイルのインスタンスを許し、**全体を 1 つに結合した版を作れること**を勧めている（木が正本、結合版は派生）。

## 4. 選択肢

| 案 | 内容 | 評価 |
|---|---|---|
| A | 今のまま（木だけ） | 携帯性・受け入れテスト・範囲外の宣言が無い |
| B | 木を全部結合して 1 ファイル | 約 33 万字。携帯できず、細部の重複が多い。**推奨しない** |
| C | **木を正本に残し、`kcaim/terrio.md` を蒸留した携帯版として並置する**（本案の試作） | 木の利点を保ちつつ、携帯性・受け入れテスト・範囲外・版の明示を得る。同期は手作業 |
| D | `kcaim/terrio.md` だけを正本にし、木をやめる | 蒸留で細部が落ちる。kcai としての実験を失う。今はしない |

## 5. 推奨と段取り（案 C）

1. **試作を盲検で試す**。`kcaim/terrio.md` から `/acceptance-tests/` の節と結果を除いたコピーを、別のエージェントに渡し、14 の質問を投げて、`result` を記入する（CONCEPT §6）。範囲外の質問（最新版、GDAL の全オプション）が正しく断れるかを見る。
2. **agent-contract の効き**を、利用者の一行プロンプトつきで試す（CONCEPT §4.2）。
3. **同期の手順**を決める。案: 新版の確認（`/procedures/recheck-on-new-version`）のたびに、`terrio.md` の版つきの事実と `/acceptance-tests/` を更新する。定期実行が push できるようになったら、その手順に含める。
4. 蒸留で落ちた細部を、どの踏み跡に残すかの対応を `kcai:` 参照で保つ。
5. 数回回して、**案 C が効くなら続け、重いなら案 B/D を再検討**する。案 D に進む判断は、盲検の結果と hfu の判断を待つ。

## 6. 試作で分かったこと

- 蒸留は**質問から逆算すると速い**。木の 46 本を順に写すより、dwg7 が実際に尋ねる質問を先に決め、答えに要る事実だけを書くほうが小さく収まる。
- **版が単位**になる。terrio の事実は「版 × インターフェース」の組で、`unit:` を宣言する意味がある。

- 木の `status: draft` の大半は「人が未確認」の意味で、kcaim の `verified`（限定つき）に素直には移せない。`/system-record/vocabulary-map` に対応表を置いた。
